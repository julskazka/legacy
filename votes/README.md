# Голоса «НАСЛЕДИЕ XXI века» — только GitHub

## Что подготовлено в этом репозитории

- `votes/votes.json`: единственный основной реестр: один ID участника Notibot → один действующий номинант.
- `votes/apply-vote.mjs`: проверяет пользователя, действующего номинанта и дату закрытия; заменяет предыдущий выбор.
- `.github/workflows/save-vote.yml`: GitHub Actions сохраняет голос в `votes/votes.json` через встроенный `GITHUB_TOKEN`, без Cloudflare или другого сервера.
- `index.html`: читает `votes/votes.json` и подсчитывает голоса.
- `votes/notibot-bridge.js`: получает данные Notibot в браузере, **но сам не может авторизованно писать в GitHub**.

## Обязательное подключение на стороне Notibot

Событие должно уходить **с защищённой серверной стороны Notibot**, а не из HTML / браузера. Нужно настроить исходящий авторизованный HTTP-запрос после нажатия «Проголосовать». Публичная документация предоставленного JS-моста подтверждает получение ID и отправку форм, но не подтверждает возможность настроить серверный HTTP-запрос. Если у Notibot нет такой функции, понадобится их поддержка / реализация со стороны платформы.

```http
POST https://api.github.com/repos/julskazka/legacy/actions/workflows/save-vote.yml/dispatches
Authorization: Bearer <SECRET_GITHUB_FINE_GRAINED_TOKEN>
Accept: application/vnd.github+json
Content-Type: application/json

{"ref":"main","inputs":{"user_id":"<SERVER_VERIFIED_NOTIBOT_USER_ID>","nominee_id":"<NOMINEE_ID>"}}
```

Для токена GitHub fine-grained: выбрать **только репозиторий** `julskazka/legacy`, разрешение **Actions: read and write**. Токен хранить только в секретах/на защищённой стороне Notibot. В `index.html`, `votes/config.js` и публичных JS токен не вставлять.

ID должен быть реальным ID из Notibot, взятым на стороне самой платформы, **не произвольной строкой из браузера**. Для Telegram/MAX-идентификаторов нужен единый стабильный формат; пример: `tg:12345` и `max:12345` во избежание столкновений.

GitHub возвращает HTTP 204 на принятый запрос запуска workflow, но это **не подтверждение записи**. Сайт должен подтвердить голос, только когда обновлённый `votes/votes.json` показывает сохранённый выбор пользователя. Сохранение может занять время, пока GitHub Actions выполняет задачу.

## Как работает запись

1. Notibot подтверждает пользователя и отправляет `user_id` + `nominee_id` в GitHub Actions.
2. Workflow скачивает последнюю ветку `main`, читает `votes/votes.json` и изменяет только запись этого участника.
3. При конкурирующей записи workflow повторяет чтение и сохранение последней версии, чтобы не затереть чужие голоса.
4. `votes/votes.json` — источник рейтинга, `votes/results.json` — старый нулевой снимок, не использовать как актуальные результаты.

**Важно:** Пока защищённый вызов из Notibot не настроен, запись с публичной страницы не работает. Нельзя включать неавторизованный вызов, размещая токен в HTML.

**Ограничения:** GitHub Actions запускается асинхронно, поэтому быстрое массовое голосование может задерживать обновление рейтинга. Публичный репозиторий и история коммитов показывают ID участников; такие идентификаторы могут быть персональными данными.

Старый Cloudflare Worker удалён из репозитория: серверная логика записи находится только в GitHub Actions.
